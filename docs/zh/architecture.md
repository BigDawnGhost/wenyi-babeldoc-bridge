# 版式规则应该放在哪里

[English](../architecture.md) · [开发环境与测试](installation.md#验证) · [HTTP 契约](api.md)

Bridge 通过 HTTP 提供一套 PDF 引擎。目录项、图例和普通段落共用抽取快照和写出流程。
按规则**修改什么、在哪个阶段能修改**确定归属，不按文档类型各建一条流水线。

| 阶段 | 负责模块（相对 `src/wenyi_babeldoc_bridge/`） | 允许的改动 |
| --- | --- | --- |
| 原生分段前 | `native.LayoutParser` 调用 `preservation/layout.py` | 只改模型检测框。可读原 PDF 证据和原生字形；不改字形文字，不分配段落 ID，不创建翻译单元。 |
| 原生分段后 | `pipeline.py` 编排 `rows.py`、`lists.py`、`annotations.py`、`protected_objects.py` 和数学规则 | 针对已有段落身份记录行边界、固定字形、标注及其偏移，不再次切分页面。 |
| 回填 | `pipeline.fillback_session`、行与标注注入、原生排版和写出 | 将校验过的译文应用到冻结图的新副本，按输出选页恢复链接。恢复会话时不重新识别目录、不加载版面模型。 |

## 原生分段前

`native.py` 运行模型，将检测结果交给原生引擎。规则的调用顺序由
`preservation/layout.py` 统一决定：先由 `boxes.py` 局部修复截断单词、图注和重音，
再由 `toc.py` 分开有充分证据的目录标题和印刷页码。两者共用 `geometry.py` 中的
模型坐标、原生框外扩取整和相交判断，不相互调用。目录证据不足或坐标不一致时，
保留普通修框的结果，不撤销前一条规则。

例如，目录规则先核对原始数字字形，再给页码单独的数字框，因此不需要翻译页码，
也不需要回填占位符。这和 `rows` 不同：前者把标题交给原生引擎分段，
后者在**已有段落内**标记条目边界。[目录准入条件及客户端行为](api.md#条目行结构)
以 API 契约为准。

## 回归验证

- 自动测试和测试辅助文件放在 `tests/`，不放进安装包。手动探针和公开样本的可选
  下载工具放在 `scripts/`。运行时不依赖两者。
- 每条规则同时测命中和容易误判的反例。规则重叠时，用同页混排样例检查无关区域不变。
  行为不变的重构要比较重构前后输出，不只比较识别数量。
- 改变字形归属时，要验证抽取、快照恢复、回填。除了段落 ID、可编辑文字和坐标，
  还要从输出 PDF 核对字形位置和选页范围内的链接目标。[样本探针](../../scripts/toc_layout_probe/README.md)
  是可选检查；默认测试不下载 PDF，也不调用翻译服务。
