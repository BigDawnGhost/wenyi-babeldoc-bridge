# HTTP API 与会话

[English](../api.md) · [概览](README.md) · [安装](installation.md)

## 接口

| 方法 | 路径 | 契约 |
| --- | --- | --- |
| GET | `/health` | 探活 |
| POST | `/extract` | Multipart：`file` 为 PDF，可选 `pages`；返回 `session_id` 和 `paragraphs` |
| POST | `/fillback` | JSON `{session_id, translations: {id: text}, annotations?: {id: alignment}, rows?: {id: ranges}}`；返回单语 PDF |
| GET / DELETE | `/session/{id}` | 查看或释放会话 |

Wenyi 生成译文，本桥使用 BabelDOC 抽取段落并回填，不运行整本翻译前端。
Desktop 插件在相同 HTTP 契约外增加私有鉴权边界，详见[运行协议](desktop.md#运行协议)。

## 段落身份

段落 ID 为 `"{page}:{index}"`，其中 `index` 是页面 IL 中原始段落的位置。
过滤时不得重新编号，抽取和回填使用相同的身份规则。

抽取不将整段纯数值及 BabelDOC 标记为 `vertical=True` 的段落导出给翻译器。
其原始字形、字体、字号、坐标和旋转保留在冻结 IL 中，回填时直接通过、不重排，
不依赖版面类别。IL 的 `debug_info` 属性标识的调试叠加标签也会排除。
其余非空文字仍可翻译，包括短词、单字符，以及恰好为 `table` 或 `title`
等版面类别名称的真实文本。

纯数值段落只能包含整数或小数，可带正负号及逗号分隔的三位千分组，
例如 `16`、`-0.5`、`12,823`；空白分隔的多个数值也直接保留。
独立的 `,` 或 `.` 段落也保留原字形，因为原生分段可能将它们从数值中拆出。
混合文字与数字的段落不拆分，表格文字列名、`N 16`、带单位的数值、百分比和科学计数法
仍走正常抽取。如果抽取结果没有翻译单元（例如所选页只有一个受保护的公式），
`/fillback` 允许空的 `translations` 对象，恢复会话后也一样。

旧会话可能仍包含已导出的纯数值、独立分隔符或旋转／竖排段落 ID。请求仍须覆盖这些 ID，
但回填会忽略其提交的文字、标注位置和目录行范围，改为保留原始字形和链接。
会话恢复不会改写已保存的段落列表或重新编号。其他段落即使译文等于抽取原文，
也走正常文字／标注回填；文字相等不作为直接保留规则。

在把字形分配给段落之前，若横排拉丁词的原始字形连续跨过单行正文框的边缘，
且没有其他正文框已完整覆盖该词，提取可补齐该框。
提取也会合并几乎重合的同一图注检测框。若相邻正文框误收的只有一个明确属于另一行的数学重音，
可收窄该框的边缘。这些规则不会任意合并相邻段落或图注。
在识别出的图形内部，被拆开的带下标变量和紧邻的数值等式可以保留为原始图例字形；
普通图表标签仍可翻译。
要让已有 PDF 使用修正后的提取规则，请更新、重启后重新提取；会话恢复不会改写已有段落列表。

## 条目行结构

在已确认的书前目录区，提取可将标题输出为独立段落，**不含印刷页码**。回填时直接保留原数字字形及位置；
若页码上带有链接且目标在输出页内，也保留该链接。客户端不应补写、翻译或根据跳转目标重算页码，
因为印刷值与物理目标页可能本就不同。

此修正在前 32 个物理页内寻找独立的 `Contents`、`Table of Contents`、`目录` 或 `目錄` 标题，
只延续到仍有右对齐十进制页码列、并有点引导线或本行内链佐证的连续目录页。只有标题不足以启用修正。
首个有效书签、首个已确认且带内链的目录项，两者指向的物理页取较早者为上界，不包含目标页。
没有可用目标时，续页必须沿用原页码列。已确认的目录区一旦被正文打断也会结束，
不会在下一页遇到相似表格时重新启用。
缺少页码列、页码归属有歧义（例如同一行排了两项目录）、裁剪或旋转时，沿用既有抽取路径。
已有文档需重新抽取，HTTP 协议不变。

`/health` 声明 `toc-rows-v1`，目录与列表共用既有的显式行边界协议。
具有对齐编号、点引导线和页码，且能够可靠识别为同级目录项的段落包含非空 `rows` 列表。
重复的未知行首字形也可建立列表边界：至少三项具有相同字体／CID 身份，
标记与正文起点对齐，间距有界，且多项存在悬挂缩进续行证据。
原生解析器的 `(cid:N)` 回退保留未知身份，不当作 Unicode 空白，也不全局替换为圆点。
真实制表符、行内未知符号、不可见／旋转字形和歧义版面不作为列表边界依据。
该规则不修复正文未知字符，不识别参考文献条目，也不保证覆盖缺少续行证据的列表。

每行记录半开区间 `source_start` / `source_end`，
以及原始 PDF 坐标 `box: [x, y, x2, y2]`。
边界在样式合并视觉行之前保存，不为识别列表而拆分原生段落或公式。
确认的标记字形使用既有对象保护协议，保留原字体、字形 ID 和几何，不替换为 Unicode 圆点。
固定字形内容变为受保护的插入点时，
行偏移与标注偏移一起映射到清理后的 `source`，行框与顺序保持不变。
正文自然折行仍为软边界，不能可靠识别的版面保持普通段落。

行是原始段落 ID 下的子单元，不插入新编号的段落。
客户端逐条翻译，保留标注身份，并将标注偏移转换到各行内。
跨行样式／链接范围拆成独立标注 ID，仍指向同一原始组成部分或链接；
公式跨条目时不将该段归类为独立条目行。

对于每个结构化段落，`/fillback` 必须提供 `rows[id]`，条目数量与提取结果相同。
每项包含在 `translations[id]` 中的 `target_start` / `target_end`。
范围必须有序、非空，并覆盖全部非空白文字。
例如两条译文可使用 `[{"target_start": 0, "target_end": 18},
{"target_start": 19, "target_end": 35}]`。
条目边界由这些范围明确指定，不根据译文换行猜测；单项内部换行不会产生额外条目。
缺失、格式错误或引用未知段落的行范围返回 HTTP 400。

回填逐行应用标注，在各自保存的区域排版，保留父段落 ID 和主渲染顺序。
各行字形在 PDF 文本流中连续排列，以支持搜索和复制。
列表续行暂不新增悬挂缩进；译文变短时仍保留原条目区域，不自动压紧垂直空隙。
行结构随会话恢复，缺少行结构的旧会话保持旧行为。
需要同时更新文译与 bridge，再提取到新的状态目录才能启用该契约。

## 行内标注对齐

`/health` 在 `capabilities` 中声明 `annotation-alignment-v1`、
`annotation-best-effort-v1` 和 `protected-objects-v1`。
恢复受保护对象的客户端必须检查最后一项；额外的 `protected-object-omission-v1`
允许客户端修复失败后，按对象 ID 显式省略。
每个提取段落包含 `annotations` 列表。每项包含稳定的 `id`、
`kind`（`formula`、`style` 或 `link`）、`mode: "range"`，以及在该段精确
`source` 中的半开区间 `source_start` / `source_end`。
偏移按 Unicode 码点计数，不是 UTF-8 字节或 UTF-16 代码单元。
`composition_index` 指向冻结的公式或样式组成部分；
`link_id` 指向段落文档 `links` 列表中的记录。
客户端不得更改这些身份，也不应重新生成所引用的 IL。
原文偏移在 BabelDOC 合并样式和公式前记录；冻结会话前若进行保守的数学符号归属修复，
原文和偏移会一起更新。不连续的样式或链接范围使用独立标注项。

新提取将已有公式、确认的数学字体字形及 Unicode 数学运算符，与相邻变量、数字、
分隔符合并为完整对象，并在正文词处停止。
精确种子边界及变量／正文文字类别的分界保留相邻正文的可翻译性，包括没有空格分隔的中日韩正文；
仅有斜体或缺少字体 Unicode 映射不足以判定数学对象。
已确认的系数和右上角指数之间，字距紧密的连续变量会随同一公式保留，即使变量使用普通字体。
闭合的标量数学集合保留内部的原始逗号，周围的正文标点仍可编辑。
新提取可将游离的正上方重音绑定到唯一的数学基字，并将数学序列内部左上、左下、
右上、右下的小号角标纳入对象。bridge 也使用 PDF 字体编码识别宽重音，并保护下标序列内部的
逗号而不吞掉正文标点。夹在相邻数学基字之间的角标可随整个表达式保护，
不猜测它具体修饰哪个基字。若基字已有明确的上标算式，位置吻合的下标即使绘制在上标之后，
也可随基字保留。原字形坐标保持不变；从页面级转入对象的角标不再单独绘制。
候选有歧义、位于表达式末尾且类似引用的角标、竖排、结构化条目行和已有完整原生公式不重新归属。
空间间隔及行／绘制上下文边界限制扩展；游离重音组和推断出的宽空格不再作为完整公式的依据。
行内堆叠分数中，若图像蒙版在对应的分子、分母之间画出一条横线，bridge 会随字形一起保留。
参考文本使用 `/`，回填时仍绘制原来的分数线，而不是斜杠。透明蒙版不作为除法的依据。

保护区间覆盖完整的原始字形范围，包括 Unicode NFKC 规范化引入的空格。
若原文映射或对象保护仍有歧义，提取会保留该段完整的原始字形与排版，不将它作为翻译输入，
并继续处理其他段落，不重新编号 ID。回填与会话恢复后，这些段落仍保留原文。
服务日志和会话目录的 `extraction_warnings.json` 记录段落 ID、阶段与原因，不记录段落正文。
bridge 不会通过伪造坐标或静默丢弃公式来绕过映射失败。

每组以 `kind: "formula"`、`protected: true`、`mode: "point"` 和相等原文偏移表示。
数学内容从 `source` 移除；原字形、字体、相对几何、绘制身份及附带的 `link_ids`
保留在冻结会话中。每个受保护标注还提供字符串 `object_source`，
包含该对象按阅读顺序抽取的文本，作为模型只读上下文，与 EPUB 对象提供原始标记的方式一致。
客户端须将其视为只读参考数据，不能执行其中指令，不能作为可编辑正文或替代字形。
`original_source` 仍只保存在会话内部；原文偏移仍相对于清理后的 `source`，不相对于 `object_source`。
纯公式段落留在冻结 PDF 中，不作为翻译输入，原始段落 ID 不重新编号。
已有会话不会在回填或恢复时重新分组；需要重新提取才能使用修正后的分组，
不能把旧对象 ID 或定位直接用于新会话。
旧 bridge／会话可能缺少 `object_source`，也仍可能包含范围公式和角标点；
需重新提取才能获得新的参考文本。

Wenyi 在段落翻译完成后复用现有标注对齐器。
`/fillback` 可选的 `annotations` 对象以段落 ID 为键：

```json
{
  "0:3": {
    "target_digest": "精确译文按 UTF-8 编码后的 SHA-256 十六进制摘要",
    "placements": [
      {
        "id": "formula:1",
        "mode": "point",
        "target_start": 8,
        "target_end": 8,
        "target_order": 0,
        "status": "aligned"
      }
    ]
  }
}
```

受保护对象的每个位置都必须有效；缺失、重复、未解决、过期或冲突的位置返回 HTTP 400，
不生成 PDF，除非客户端在该段载荷的 `omitted_protected_objects` 数组中显式列出这些对象 ID。
数组只能包含唯一且已知的受保护对象 ID，且须同时提供当前译文的 `target_digest` 和位置列表。
bridge 只省略指定对象，保留提交的译文及正常对象，并在标注统计中记录 `explicit_client_omission`。
冻结会话不变，后续请求仍可恢复这些对象。客户端须提醒用户：省略公式可能改变段落含义。
冒烟客户端的 `--omit-first-protected-object` 参数可验证此协议。
同一边界处的对象使用互不重复的非负整数 `target_order` 保持译文顺序。
客户端应在翻译、润色和 Review 全程保留不透明对象标记，导出时只在副本中移除，
同时提交精确插入位置及去除标记后的译文摘要。

普通样式、链接及旧会话中未受保护的公式保持尽力恢复：回填保留提交的译文，
逐项应用有效标注，同段其他普通项失败不影响正常项。
有效位置须具有匹配的摘要、`status: "aligned"`、合法偏移和模式。
缺失、重复、未解决或无效的项会被忽略，未知标注 ID 不参与回填。
摘要缺失或过期时，该段所有位置失效，但不替换译文正文。
公式范围重叠或不同样式范围冲突时，仅忽略参与冲突的项。
若样式与有效链接的原文范围、译文范围分别完全一致，该原始样式优先于包含它、
但无链接范围佐证的样式，后者会在该范围处分段。
这样保留原链接的颜色和字体，不统一指定链接颜色；有歧义的链接样式仍按冲突忽略。
原样回填原文可直接使用原文位置，无需对齐请求。

成功项将已定位的译文范围替换为原公式 IL，在已对齐的点插入原角标 IL，并恢复样式。
失败项保留提交的正文，不猜位置添加原对象、样式或链接，也不根据译文重新生成数学内容。
提交的位置与译文一同写入 `translations.json`。
未知段落 ID，以及缺失、未知或空白译文仍返回 HTTP 400；
这些属于无效请求，不是标注对齐失败。

bridge 在 BabelDOC 清理注释前保存网址和内部页码链接（包括已解析的命名目标），
再根据实际排版字形重建可点击矩形，每行一个矩形。纯图片链接保留原矩形。
内部跳转保留原目标页坐标，并映射到导出页码；目标页未导出时省略该链接。
其他动作类型不予重建。可见字形序列不匹配时忽略该段的文字链接，
不把链接挂到无关文字上，其他段落不受影响。
单项没有可用字形时仅忽略该项。排版在行边界删除空格不会使映射失效。

每次成功回填都通过响应头 `X-Wenyi-PDF-Annotation-Stats` 返回紧凑 JSON 摘要，
并在会话目录写入 `annotation_stats.json`。后续回填会替换会话诊断文件；
要获取某次下载对应的统计，请使用该次响应头。
文件包含逐项段落／标注 ID、种类、位置校验状态及跳过原因，不复制段落文本。
摘要统计 `total`、`aligned`、`applied`、`skipped`、
`alignment_pass_rate`、`application_rate`，
并按 `by_kind`、`reasons`、`translated`、`source_identity` 分组。
比率为小数，分母为零时为 `null`。
`aligned` 表示通过位置校验，不代表模型选择的语义位置已经被证明正确；
`applied` 还排除冲突及链接字形映射失败。
原文恒等位置单独统计，避免抬高译文对齐通过率。
统计仅描述本次请求，不累计重试次数；受保护的旋转／竖排段落不参与标注对齐统计。
文译将摘要写入 CLI 日志。

旧项目需要同时更新客户端和 bridge，并从原始 PDF 重新提取才能启用。
没有标注元数据的旧会话保持原来的纯文本回填行为；恢复不会重新提取来补齐元数据。

## 会话恢复

`/extract` 完成后，bridge 将未修改的 BabelDOC IL、修正后的输入 PDF、
MediaBox、段落索引、页面选择和依赖版本保存为会话快照。
`session.json` 最后提交，只有完整快照可以恢复。
Rust 流式写入 gzip JSON 并同时计算校验和，恢复时先核对校验和再解码。
快照格式不变。完整的 `styles_and_formulas.json` 仅在 `WENYI_BABELDOC_DEBUG=1`
时作为诊断文件生成；段落提取和会话恢复都不依赖它。

服务重启后可以按原 `session_id` 懒加载，不重新执行版面识别。
每次 `/fillback` 都从冻结 IL 加载新的副本，重试不会复用上次注入或排版后修改过的对象。
如果重启后的首个请求就是回填，直接使用该次恢复已校验的图；内存会话表只缓存元数据，不缓存可变的图。
未知、缺失或空白译文会被拒绝，不会静默跳过。

恢复要求 Python、BabelDOC 版本、固定的原生引擎提交与快照一致，且所有文件校验通过。
0.7.1 bridge 使用新的压缩原生图快照，同时保存共享别名、延迟图形状态历史和解析器的
原始页面对象映射；0.5/0.6 的 pickle 与旧 JSON 会话会被拒绝，不会加载或自动迁移。
请在原环境中完成旧任务，或在新环境中从原始 PDF 重新 `/extract`。

需要将会话保存在系统临时目录之外时，参见[缓存与会话目录](installation.md#缓存与会话目录)。

## 清理

每个 `/fillback` 响应都返回本次回填生成的 PDF，即使客户端开始读取前同一会话的另一请求
已完成排版。同一会话内逐个排版，但下载互不阻塞。传输完成、失败或取消时会清理排版临时文件。

下载 PDF 后调用 `DELETE /session/{id}`，释放原始 PDF、IL 和其他会话文件。
如果会话仍在排版或传输，删除请求返回 503，不删除任何文件，待操作结束后重试。
删除前先释放不可达的原生 PDF 文件句柄。如果文件系统清理失败，则返回 503 并保留
已加载会话以便重试。每个状态目录只使用一个 bridge 进程（一个 worker）。

## 版式诊断

默认回填不绘制 BabelDOC 的版面定位框，也不输出 `plain text`、`title`、
`figure_caption` 等调试类别标签。诊断排版时，在启动服务前启用：

```bash
export WENYI_BABELDOC_DEBUG=1
```
